# Kubcrafter: деньги

Инструмент учёта денег вместо Финолога. Один файл `index.html` без сборщика: работает как веб-приложение на экране «Домой» iPhone и на компьютере. Данные хранятся в браузере, при подключении Firebase синхронизируются между устройствами. В репозитории нет данных, только оболочка и код.

## Состав репозитория

| Файл или папка | Зачем |
|---|---|
| `index.html` | сам инструмент (логика и интерфейс в одном файле), его отдаёт GitHub Pages |
| `config.js` | настройки: тестовая или рабочая база, офлайн-режим, конфигурация Firebase |
| `config.example.js` | пример настроек с подключённым Firebase |
| `firestore.rules` | правила доступа к базе: только адреса из списка |
| `firebase.json`, `.firebaserc`, `firestore.indexes.json` | для выкладки правил через Firebase CLI |
| `sw.js`, `manifest.webmanifest`, `icon-180.png` | работа без связи и значок на экране «Домой» |
| `src/` | исходный код, сборка и тесты |
| `apps-script/statements.gs` | скрипт Google Apps Script для кнопки «Синхронизировать выписки» |
| `HANDOFF.md` | устройство инструмента и порядок проверки |
| `CLAUDE.md` | инструкция для Claude Code |

## Что проверено, а что нет

Проверено: 139 автоматических проверок логики, 97 проверок интерфейса в настоящем браузере на размерах телефона и компьютера и 14 проверок обмена между двумя устройствами на имитации Firestore. Проверялись ввод по Enter, подсказки, перевод одним действием, поиск по тексту и сумме, сверка тестовых выписок, копия и восстановление, справочник статей, завершение проекта, обе темы.

Не проверено: iPhone и Safari (офлайн, значок «Домой», кнопка «Далее» на клавиатуре), чтение настоящих xlsx-выписок (форматы Альфы и Промоса не просматривались), живое подключение к Firebase и вход через Google, сервис-воркер, внешний вид со шрифтом Montserrat.

## Выкладка

Названия пунктов в консолях GitHub и Firebase могут отличаться от описанных: код этих шагов не проверялся на вашем проекте.

### Шаг 1. GitHub Pages (без облака)

1. Создайте репозиторий на GitHub и загрузите в него всё содержимое этой папки (в корень).
2. Settings, Pages, источник: ветка `main`, папка `/ (root)`.
3. Откройте адрес вида `https://<логин>.github.io/<репозиторий>/` на iPhone в Safari, Поделиться, «На экран Домой».

Пока облако не подключено, данные лежат только в памяти браузера: телефон и компьютер между собой не синхронизируются. Делайте копию (Настройки, «Данные и копии») после каждого заполнения.

### Шаг 2. Firebase (синхронизация между устройствами)

1. Создайте новый проект Firebase только для денег. Проект дашборда заказов использовать нельзя.
2. Authentication, способ входа Google. В разрешённых доменах добавьте `<логин>.github.io`.
3. Включите двухфакторную защиту на аккаунте Google, под которым будете входить.
4. Firestore Database: создайте базу в режиме production. Регион выбирается один раз, потом его не изменить.
5. Настройки проекта, ваши приложения, веб-приложение: скопируйте конфигурацию в `config.js` в поле `firebase` (образец в `config.example.js`). Эти значения не секретны: защита данных обеспечивается входом Google и правилами доступа.
6. В `firestore.rules` замените `ЗАМЕНИТЕ@gmail.com` на адрес Google. В `.firebaserc` замените `ВАШ-ПРОЕКТ` на идентификатор проекта.
7. Выложите правила:
   ```
   npm install -g firebase-tools
   firebase login
   firebase deploy --only firestore:rules
   ```
8. Закоммитьте `config.js` и обновите страницу. В инструменте: Настройки, «Данные и копии», «Войти через Google».

В облако уходят операции, справочник статей, статусы проектов, решения по выпискам, история загрузок и журнал изменений.

### Права

У всех адресов из списка в `firestore.rules` полные права, включая настройки статей, отдельных ролей нет. Чтобы дать доступ ещё одному человеку, допишите его адрес Google в список и выложите правила заново.

## Автозагрузка выписок (кнопка «Синхронизировать выписки»)

Кнопка в разделе «Выписки» читает папку с выписками на Google Диске через небольшой скрипт Apps Script в вашем аккаунте. Скрипт видит только эту папку и отдаёт файлы только по секретной ссылке. Какой банк, определяется по названию файла: «Промос» в названии значит Промос, «Выписка…» (или номер счёта Альфы) значит Альфа. Файл с другим названием не загружается, об этом пишется в сообщении. Уже прочитанные файлы (по ID, размеру и дате изменения) пропускаются: «Новых выписок не найдено». Если файл изменили, он читается снова, дублей строк не будет.

Настройка (один раз, названия пунктов в консоли Google могут отличаться):
1. Откройте https://script.google.com, «Новый проект», вставьте код из `apps-script/statements.gs`.
2. В первой строке замените `ВСТАВЬТЕ_ID_ПАПКИ` на идентификатор папки (часть ссылки после `/folders/`).
3. Выберите функцию `setup`, нажмите «Выполнить» и дайте разрешения (доступ к Диску).
4. «Начать развёртывание», «Новое развёртывание», тип «Веб-приложение»: «Выполнять от имени: я», «Доступ: все». Скопируйте адрес.
5. Выберите функцию `showLink`, выполните и откройте журнал выполнения: там ссылка вида `https://script.google.com/macros/s/…/exec?key=…`. Она секретна, как пароль (ключ внутри ссылки).
6. В инструменте: «Выписки», поле «Ссылка скрипта выписок», вставьте ссылку и нажмите «Сохранить ссылку». Для рабочей и тестовой баз ссылка сохраняется отдельно.

Если скрипт изменили, нужно «Управление развёртываниями», карандаш, «Новая версия», «Развернуть» (адрес и ключ не меняются). Версия скрипта с параметром `callback` нужна для iPhone: Safari блокирует обычный запрос между сайтами, и инструмент тогда загружает ответ скриптом-вставкой. Чтобы отозвать доступ: удалите развёртывание или свойство `KEY` в настройках проекта скрипта.

## Тестовая и рабочая базы

Базы раздельные: у тестовой и рабочей свои ключи в браузере и свои коллекции в облаке (`money_test_*` и `money_prod_*`). По умолчанию доступна только тестовая. Когда проверка пройдёт, в `config.js` поставьте `allowProd: true`, и в Настройках появится переключатель на рабочую базу.

План запуска: пустая оболочка, пять тестовых строк из сводной таблицы (Настройки, «Данные и копии», «Импорт сводной таблицы», поле «Сколько строк загрузить»), проверка Дмитрием, сброс тестовой базы целиком, затем полная загрузка в рабочую.

## Справочник статей

Статьи фиксированы: в формах записей они только выбираются из списка, свободный ввод невозможен. Названия, вид статьи (приход или расход), вид деятельности (операционная, инвестиционная, финансовая) и признак «постоянная» меняются только в разделе «Настройки», вкладка «Статьи». При загрузке сводной таблицы статьи из неё добавляются в справочник сами, вид деятельности указывается в Настройках. Статья, по которой есть операции, не удаляется, а уходит в архив. На справочнике будет построена финансовая модель.

## Копии

Кнопка «Скачать копию» отдаёт xlsx для просмотра и JSON для восстановления. Автоматическая еженедельная копия на Google Диск в этой версии не работает: для неё нужен серверный планировщик. Инструмент напоминает, если копия не делалась 7 дней. Файлы копий и любые выписки в репозиторий не коммитятся: это закрыто в `.gitignore`.
