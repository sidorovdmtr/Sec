## Что это

Веб-инструмент учёта денег вместо Финолога (подписка до ~21.11.2026). Один файл `index.html` без сборщика. Данные хранятся локально в браузере (IndexedDB; если недоступен, localStorage: на iPhone там около 5 МБ на сайт, этого не хватало для рабочей и тестовой баз вместе), при подключённом Firebase синхронизируются с Firestore. Рабочая база включена (`allowProd: true`), тестовая раздельная и нужна для проверок.

## Состав

- Корень репозитория: то, что отдаёт GitHub Pages (`index.html`, `config.js`, `config.example.js`, `sw.js`, `manifest.webmanifest`, `icon-180.png`) и файлы Firebase (`firestore.rules`, `firebase.json`, `.firebaserc`, `firestore.indexes.json`). Шаги выкладки в `README.md`.
- `src/core.js`: вся логика без интерфейса (остатки, переводы, сверка выписок, поиск, подсказки, справочник статей, завершение проекта, анализ закрытых проектов, слияние с облаком). Работает в браузере и в Node.
- `src/app.js`: интерфейс, хранилище (IndexedDB), копии, синхронизация с Firebase, кнопка «Синхронизировать выписки», режим администратора.
- `src/style.css`: две темы (тёмная и светлая), шрифт Montserrat.
- `src/build.py`: собирает `src/dist/artifact.html` и `src/dist/deploy/index.html` из core.js, app.js и style.css и копирует готовый `index.html` в корень репозитория.
- `apps-script/statements.gs`: скрипт Google Apps Script для кнопки «Синхронизировать выписки» (код без секретов; папка и ключ задаются в проекте скрипта у Дмитрия).
- Тесты: `src/test_core.js` (логика, Node), `src/test_ui.js` (интерфейс, Playwright), `src/test_sync.js` (два устройства на имитации Firestore), `src/test_storage.js` (IndexedDB и перенос), `src/test_stmsync.js` (кнопка выписок, ручная загрузка, исправление дат; нужна библиотека xlsx), `src/test_admin.js` (режим администратора, анализ проектов, свёрнутые списки).

## Как собрать и проверить

```
cd src
node test_core.js
python3 build.py
NODE_PATH=<путь к node_modules с playwright> node test_ui.js dist/deploy/index.html
NODE_PATH=<путь к node_modules с playwright> node test_sync.js
NODE_PATH=<путь к node_modules с playwright> node test_storage.js dist/deploy/index.html
NODE_PATH=<путь к node_modules с playwright> node test_stmsync.js dist/deploy/index.html <путь к node_modules/xlsx/dist/xlsx.full.min.js>
NODE_PATH=<путь к node_modules с playwright> node test_admin.js dist/deploy/index.html
```

Библиотеку xlsx для `test_stmsync.js` ставить в отдельную папку вне репозитория (`npm i xlsx@0.18.5`). В остальных тестах внешние адреса заблокированы, xlsx и шрифты недоступны. Тесты интерфейса включают режим администратора через `KCApp.setAdmin(true)` и раскрывают списки через `KCApp.S.artListOpen` и `KCApp.S.logOpen`. Состояние на 02.11.2026: логика 168, интерфейс 102, обмен 27, хранилище 6, кнопка выписок 32, режим и блоки 43, все проходят.

## Модель данных

- Запись: `id`, `kind` (expense, income, transfer_out, transfer_in), `wallet` (alfa, cash, promos, credit), `amount` в копейках со знаком, `date`, `planned`, `counterparty`, `article`, `project`, `description`, `bankState` (none, unconfirmed, confirmed, absent; старое `pending` читается как `unconfirmed`), `bankKey`, `pairId` (текст «пары не найдено» не считается парой), `source`, `extId` (номер строки сводной), `dateFixed`, `deleted` (мягкое удаление), `updatedAt`.
- Справочник статей: `id`, `name`, `kind`, `activity` (operating, investing, financing, none), `fixed`, `archived`, `system`, `updatedAt`. Статья в записи хранится названием.
- Проекты: `meta.projects[название] = { status: 'done'|'work', doneAt, result: { income, variable, fixedAllocated, net, … } }`. Результат закрытого проекта сохраняется снимком в момент закрытия.
- Облако Firestore: коллекция `money_<test|prod>_records` (документ на запись) и `money_<test|prod>_meta` с документами `state` (справочник, проекты), `decisions`, `log`, `settings` (ссылка скрипта выписок со временем изменения и список прочитанных файлов). Слияние по времени последней правки.
- Правила доступа: `firestore.rules`, список адресов с полными правами.

## Ключевые правила поведения

- Остаток кошелька включает все неподтверждённые выпиской записи (статус «Не подтверждено выпиской»), понятия «в пути» нет. Промос считается по учёту Дмитрия. Кредитный счёт личных средств вне общего итога.
- Перевод создаёт две парные записи, обе видны в журнале. Переводы и записи со статьёй «Корректировка остатка» не входят в отчёты и оборот, в остатки входят.
- Сверка выписки: кошелёк, сумма, дата ±4 дня для неподтверждённых записей; точная дата и сумма для уже подтверждённых без ключа выписки (привязка без дубля); дневная комиссия одной строкой привязывается к группе комиссий по платежам (сумма группы равна строке).
- Загрузка выписки (кнопка «Синхронизировать выписки» и ручная) сначала показывает окно с цифрами (строк, привязать, добавить новых с суммой, дубли, решения) и вносит данные только после подтверждения Дмитрия.
- Кнопка читает одну папку на Диске через скрипт Apps Script; банк по названию файла («Промос» значит Промос, «Выписка…» значит Альфа); файл должен заканчиваться на `.xlsx` или `.xls` (Диск при копировании добавляет «Копия (…)», такой файл нужно переименовать). Для iPhone ответ грузится скриптом-вставкой (JSONP).
- Режим администратора (выключатель внизу «Настроек», по умолчанию выключен, сбрасывается при перезапуске) показывает служебное: импорт сводной, исправление дат, восстановление из копии, сброс и тестовые данные, переключатель базы, ссылку скрипта, «Проверить связь», «Прогнать тестовую выписку».
- «Сбросить тестовую базу» чистит устройство и облако тестовой базы; сбрасывать нужно на каждом устройстве.
- Финансовый анализ на экране «Проекты» считается только по закрытым проектам, период по дате закрытия, результат из снимка при закрытии; блок свёрнут по умолчанию. Список проектов ниже за всё время.
- Список статей и журнал изменений в «Настройках» свёрнуты по умолчанию.
- Статьи в формах только выбираются из справочника, менять их можно только в Настройках. Enter в поле «Описание» сохраняет запись.
- Даты из xlsx: библиотека в поясе Москвы отдаёт полночь как 23:59:43 предыдущего дня; к дате прибавляется 10 минут (исправлено 02.11.2026). Кнопка «Исправить даты импорта» нужна только для данных, загруженных до исправления; в рабочей базе уже применена.

## Что не проверено

- Живая Firebase проверялась только на имитации и руками Дмитрия на iPhone; настоящая новая выписка (с новыми строками) через кнопку не проверялась, обе имеющиеся выписки уже полностью учтены.
- Пересылка выписок с почты в папку не сделана (выписки Альфы приходят на Яндекс Почту, Дмитрий переводит на Gmail; нужны адрес отправителя и тема письма, содержимое писем не читать).
- Блок анализа проектов проверен только на тестовых данных: ни один проект ещё не закрыт.
