## Что это

Веб-инструмент учёта денег вместо Финолога (подписка до ~21.11.2026). Один файл `index.html` без сборщика. Данные хранятся локально в браузере (IndexedDB; если недоступен, localStorage: на iPhone там около 5 МБ на сайт, этого не хватало для рабочей и тестовой баз вместе), при подключённом Firebase синхронизируются с Firestore. Тестовая и рабочая базы раздельные.

## Состав

- Корень репозитория: то, что отдаёт GitHub Pages (`index.html`, `config.js`, `config.example.js`, `sw.js`, `manifest.webmanifest`, `icon-180.png`) и файлы Firebase (`firestore.rules`, `firebase.json`, `.firebaserc`, `firestore.indexes.json`). Шаги выкладки в `README.md`.
- `src/core.js`: вся логика без интерфейса (остатки, переводы, сверка выписок, поиск, подсказки, справочник статей, завершение проекта, слияние с облаком). Работает в браузере и в Node.
- `src/app.js`: интерфейс, хранилище, копии, синхронизация с Firebase.
- `src/style.css`: две темы (тёмная и светлая), шрифт Montserrat.
- `src/build.py`: собирает `src/dist/artifact.html` и `src/dist/deploy/index.html` из core.js, app.js и style.css и копирует готовый `index.html` в корень репозитория.
- `src/test_core.js` (139 проверок, Node), `src/test_ui.js` (97 проверок, Playwright в Chromium), `src/test_sync.js` (14 проверок обмена двух устройств на имитации Firestore).

## Как собрать и проверить

```
cd src
node test_core.js
python3 build.py
NODE_PATH=<путь к node_modules с playwright> node test_ui.js dist/deploy/index.html
NODE_PATH=<путь к node_modules с playwright> node test_sync.js
NODE_PATH=<путь к node_modules с playwright> node test_storage.js dist/deploy/index.html
NODE_PATH=<путь к node_modules с playwright> node test_stmsync.js dist/deploy/index.html <путь к node_modules/xlsx/dist/xlsx.full.min.js>
```

Тесты интерфейса грузят страницу из файла и блокируют внешние адреса, поэтому библиотека xlsx (SheetJS с cdnjs) и шрифты в тестах недоступны.

## Модель данных

- Запись: `id`, `kind` (expense, income, transfer_out, transfer_in), `wallet` (alfa, cash, promos, credit), `amount` в копейках со знаком, `date`, `planned`, `counterparty`, `article`, `project`, `description`, `bankState` (none, pending, unconfirmed, confirmed, absent), `bankKey`, `pairId`, `source`, `deleted` (мягкое удаление), `updatedAt`.
- Справочник статей: `id`, `name`, `kind`, `activity` (operating, investing, financing, none), `fixed`, `archived`, `system`, `updatedAt`. В записях статья хранится названием, переименование обновляет записи. Удалённые статьи хранятся метками.
- Облако Firestore: коллекция `money_<test|prod>_records` (документ на запись) и `money_<test|prod>_meta` с документами `state` (справочник, статусы проектов), `decisions` (решения по выпискам, игнорируемые строки, история загрузок) и `log` (журнал). Слияние идёт по времени последней правки, решённые вопросы по выпискам не воскресают.
- Правила доступа: `firestore.rules`, список адресов с полными правами, ролей нет.

## Ключевые правила поведения

- Остаток банковского кошелька равен выписке, неподтверждённое показывается «в пути». Промос считается по учёту Дмитрия, неподтверждённое входит в остаток. Кредитный счёт личных средств вне общего итога.
- Перевод вводится одним действием и создаёт две парные записи. Сверка с выпиской: кошелёк, направление, сумма, дата с допуском 4 дня.
- Статьи в формах только выбираются из справочника, менять их можно только в Настройках.
- Завершение проекта: период между первым и последним платежом заказчика (или свой), состав расчёта (поступления с галочками, постоянные статьи из справочника), постоянные расходы периода распределяются по доле поступлений заказа.
- Enter в поле «Описание» сохраняет запись и закрывает окно.

## Что не проверено

- Живое подключение к Firebase и вход через Google: код есть, проверялся только на имитации.
- iPhone и Safari: офлайн, значок на экране «Домой», клавиатура с «Далее», сервис-воркер.
- Чтение настоящих xlsx выписок Альфы и Промоса: форматы не просматривались, в интерфейсе колонки сопоставляются вручную; автоопределение нужно настроить по настоящим файлам.
- Импорт сводной таблицы (колонки Финолога) проверен только на выдуманных строках.

## Ближайшие шаги

1. Дмитрий проверяет сводную таблицу и разрешает прочитать нужный файл. Читать только его, персональные данные в документы не копировать.
2. Настроить импорт под настоящие файлы, сверить список статей и видов деятельности с Дмитрием.
3. Выложить репозиторий на GitHub Pages, создать отдельный проект Firebase, вставить конфигурацию в `config.js`, заменить адрес в `firestore.rules`, выложить правила (шаги в `README.md`).
4. Запуск: пустая оболочка, пять тестовых строк из сводной таблицы, подтверждение Дмитрия, сброс тестовой базы, полная загрузка в рабочую.
5. Автозагрузка выписок Альфы (скрипт Google Apps Script кладёт xlsx в папку «Выписки / новые» на Диске), еженедельная копия на Диск (нужен серверный планировщик).
